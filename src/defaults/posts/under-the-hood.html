A short tour of how a request becomes a page.

1. files, not tables

Every piece of the site is a file in the data directory. Writes go to a temporary file first and are renamed into place, so a reader never sees half a stylesheet. A backup is tar czf site.tgz /var/lib/zerverg.

2. a layout is a tree

The XML layout is parsed by a deliberately tiny parser: no DTDs, no external entities, no surprises. It is validated when you upload it, then rendered component by component into HTML with zv-* classes.

3. the page is assembled

  1. pick the layout: the entry's own, else the site's active one
  2. take the <body> of the entry's HTML
  3. expand <zv-entries> placeholders
  4. rewrite media: references
  5. drop it into <main/>, add style and snippets

4. nothing is lost

Layouts, styles and snippets keep their last versions. Broke the theme at 2am? Roll back with one request.

The source is small enough to read in an evening. Start at src/main.zig.
