api

Everything the admin can do goes through a small REST API under /api/v1. The admin web UI uses the same endpoints.

authentication

Two ways in:

  • HTTP Basic on every request. Simplest for scripts.
  • Session cookie from POST /auth/login. Used by the web UI. Requests that change anything must also send X-Requested-With: zerverg (CSRF protection).
curl -u admin:secret http://localhost:7080/api/v1/posts

curl -c jar -H 'X-Requested-With: zerverg' \
     -d '{"username":"admin","password":"secret"}' \
     http://localhost:7080/api/v1/auth/login

In --dev mode authentication is disabled.

site settings

curl -u admin:secret -X PUT http://localhost:7080/api/v1/site -d '{
  "title": "my site",
  "active_layout": "default",
  "active_style": "default",
  "enabled_snippets": ["terminal"]
}'

examples

# publish a post
curl -u admin:secret -X PUT --data-binary @post.html \
     http://localhost:7080/api/v1/posts/hello-again

# upload a stylesheet and switch to it
curl -u admin:secret -X PUT --data-binary @light.css \
     http://localhost:7080/api/v1/styles/light

# upload an image
curl -u admin:secret -X PUT --data-binary @cat.png \
     http://localhost:7080/api/v1/media/cat.png

# undo the last style change
curl -u admin:secret -X POST \
     "http://localhost:7080/api/v1/styles/light/rollback?version=1"
